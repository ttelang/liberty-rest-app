:toc:
:icons: font

This project is a simple Hello World microservice built with Jakarta EE 10 and MicroProfile 6.1, running on Open Liberty.

== Overview

The Hello World microservice is a demonstration of basic Jakarta EE and MicroProfile functionality. 
It provides a simple REST endpoint that returns a greeting message. The application showcases various 
Jakarta EE and MicroProfile features.

== Features

* Jakarta EE 10 Web Profile
* MicroProfile 6.1
* REST API using JAX-RS
* JSP-based web interface
* Custom ports configuration (HTTP: 2010, HTTPS: 2011)

== Prerequisites

* Java 17 or later
* Maven 3.6+

== Quick Start

=== Building the Application

[source,bash]
----
cd hello-world
mvn clean package
----

=== Running the Application

[source,bash]
----
mvn liberty:dev
----

This will start the Liberty server in development mode, which enables hot reloading of application changes.

=== Accessing the Application

* Web Interface: http://localhost:2010/hello-world/
* REST Endpoint: http://localhost:2010/hello-world/api/hello

== Configuration

=== server.xml

The Liberty server is configured with the following features:

* servlet-6.0
* pages-3.1
* cdi-4.0 
* restfulWS-3.1
* jsonb-3.0
* jsonp-2.1

The HTTP and HTTPS ports are configured to 2010 and 2011 respectively.

=== pom.xml

Key configurations in the Maven POM file:

* Jakarta EE 10 and MicroProfile 6.1 dependencies
* Liberty Maven Plugin for building and running the application
* Custom port configuration
* Context root set to `/hello-world`

== Development

=== Hot Reloading

When running in development mode using `mvn liberty:dev`, changes to your code will be automatically detected and the application will be rebuilt and redeployed.

=== Debugging

To start the server in debug mode, use:

[source,bash]
----
mvn liberty:dev -Dliberty.debug.port=7777
----

Then connect your IDE to port 7777.

== Troubleshooting

=== Port Already in Use

If you encounter an error like `CWWKO0219E: The TCP port 2010 is already in use`, another process is using the configured port. To resolve this issue:

1. Find the process using the port:

[source,bash]
----
lsof -i :2010
# or
netstat -tulpn | grep 2010
----

2. Either stop the conflicting process or change the port in your configuration:

* Modify `server.xml`:
+
[source,xml]
----
<httpEndpoint httpPort="2020" httpsPort="2021"
    id="defaultHttpEndpoint" host="*" />
----

* Update the corresponding properties in `pom.xml`:
+
[source,xml]
----
<liberty.var.default.http.port>2020</liberty.var.default.http.port>
<liberty.var.default.https.port>2021</liberty.var.default.https.port>
----

=== Missing JSP File Error

If you encounter a `File not found: /index.jsp` error when accessing the application:

1. Verify the index.jsp file exists in the correct location:
+
[source,bash]
----
ls -la src/main/webapp/index.jsp
----

2. Ensure the webapp directory structure is correct:
+
[source]
----
src/main/webapp/
├── WEB-INF/
│   └── web.xml
└── index.jsp
----

3. Check that the welcome file is properly configured in `web.xml`:
+
[source,xml]
----
<welcome-file-list>
  <welcome-file>index.jsp</welcome-file>
  <welcome-file>index.html</welcome-file>
</welcome-file-list>
----

4. Rebuild the application and restart the server:
+
[source,bash]
----
mvn clean package
mvn liberty:dev
----

5. Verify the context root in both `server.xml` and `pom.xml` match your expectations.

=== Checking Server Logs

When troubleshooting issues with your Liberty application, examining the server logs is essential:

1. Default log locations when running with the Liberty Maven Plugin:
+
[source]
----
target/liberty/wlp/usr/servers/defaultServer/logs/
├── console.log            # Basic server output and status messages
├── messages.log           # Detailed server messages and errors
├── trace.log              # Fine-grained trace information (if enabled)
├── ffdc/                  # First Failure Data Capture directory
└── state/                 # Server state information
----

2. View the most recent entries in the console log:
+
[source,bash]
----
tail -f target/liberty/wlp/usr/servers/defaultServer/logs/console.log
----

3. Search for specific errors in the messages log:
+
[source,bash]
----
grep -i error target/liberty/wlp/usr/servers/defaultServer/logs/messages.log
----

4. Enable more detailed trace for specific components by adding these lines to `server.xml`:
+
[source,xml]
----
<logging traceSpecification="com.example.*=all"
         maxFiles="5" 
         maxFileSize="20" 
         traceFormat="ENHANCED"/>
----

5. Common error codes to look for:
* `CWWKZ0002E` - Application deployment failures
* `CWWKO0219E` - Port conflicts
* `SRVE0777E` - Servlet/JSP exceptions
* `CWWKE0701E` - Insufficient memory errors
